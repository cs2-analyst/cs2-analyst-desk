# P8 AI Coach 技术路线

日期：2026-10-15。状态：技术路线设计，尚未开始实现；本轮只更新文档，不创建运行时模块、数据库或模型调用。

本版架构决定：内部知识积累与 AI 分析在同一 monorepo 中各自规划为独立后端应用，独立构建和部署；取代上一版把职业知识库和模型编排放在 Desktop 的路线。下文应用路径均为规划名称，目录尚未创建。

## 1. 目标与范围


> **当前范围修订（2026-10-25）：** 本路线以 [L1/L2 范围决策](./p8-scope-decision-l1-l2-2026-10-25.md) 为准：只做服务器事实复盘与经验证的空间/行动条件分析；不实现 POV 分析或推断玩家注意力。服务器全局状态不等于玩家已知信息。地图几何未验证时不得输出确定性路线/LOS 结论；未来事件不得改变历史输入或采样。P8.1B 原始 BLOCKED 记录保留并需按新范围复核，P8.1C/D 不自动放行，P8.2 仍需独立授权。

通过持续导入职业 DEM，把可核验经验沉淀为项目拥有的规则、案例与评测资产。不同 AI 模型读取同一套知识、证据和分析规范；模型切换无需重新整理知识，但效果必须分别验证。

- 产品目标：从用户的问题出发分析个人操作与决策，同时支持职业选手个人决策复盘。
- 首批范围：Dust2 的 1v1 残局；关注空间利用、选位、暴露时机、转移与道具选择。
- 长期方向：在证据和验证能力成熟后扩展地图及 1vN；不承诺唯一“完美方案”或未经校准的最优胜率。
- 手动补充报点、声音与主观已知信息后续再做。首版缺失信息明确标为未知，不默认选手知道全局敌情。
- 本文确定技术分层与演进顺序；具体样本字段、标注手册、评分阈值和 UI 在对应工作单元启动前另行定义。

## 2. 技术选择

| 方面 | 本阶段路线 | 边界 |
| --- | --- | --- |
| 语言与运行 | 沿用 TypeScript、pnpm；Desktop 保留本地分析，知识与 AI 服务使用独立后端运行时 | 复用公共领域包，不另建 Python 统计管线，不重复实现现有指标 |
| 应用拆分 | 规划 `apps/knowledge-pipeline` 内部知识管线与 `apps/coach-api` AI 分析服务 | 同一 monorepo、独立构建部署；不拆仓库，不把后端入口或私有资产打进客户端 |
| 学习方式 | 外部知识积累：证据提取、候选规律、审核、验证、版本发布 | 不以参数微调或强化学习作为首版前提；导入 DEM 不等于模型权重更新 |
| 持久化 | 知识管线后端私有 SQLite 保存案例、候选规律、审核记录、规则版本与评测运行 | 首版按单写入部署验证；不共享多写者数据库，不把职业知识库存入 Desktop，不引入个人比赛历史库 |
| 可迁移资产 | 后端保存 Markdown Prompt 与版本化 JSON 规则/知识快照/评测配置 | SQLite 管理草稿与审核状态，已发布知识导出为不可变内部快照并记录摘要；快照不对客户端下载 |
| 检索 | 结构化条件过滤与适用条件匹配，必要时辅助全文检索 | 不以相同地点名称或最近坐标代替决策理解；向量检索不作为首版依赖 |
| 模型接入 | 后端统一模型适配接口；Desktop 只调用应用自有 AI 分析 API | 供应商 SDK、模型密钥、系统 Prompt 与完整职业知识仅在后端；不依赖厂商专属记忆 |
| 地图推理 | P6/P7 使用客户端地图基础；后端维护版本匹配的拓扑与经验证的几何查询 | 服务端校验地图版本与能力，不能把客户端空间推断直接当作已验证事实；2D 图像不证明 LOS |
| 结果展示 | Fluent UI v9，复用回合证据跳转及 P6 回放入口 | AI 建议与确定性 Findings 分开展示，不覆盖原始统计或原诊断 |

SQLite 具体 Node 绑定、后端部署/备份方式、全文分词与检索效果需在实现前验证；不再增加客户端 SQLite 打包任务。本次不引入依赖。知识管线是知识草稿库的唯一写入方；AI 分析服务只加载经审核发布的只读快照，不直接访问草稿、保留集或共享可写数据库。多副本和数据库迁移需求留待实际容量与并发证据支持后再评估。

当前 native DEM parser 仅已验证 Windows x64。内部知识管线复用它时，部署环境与 native 绑定必须单独验证；不得假定后端天然支持 Linux 或跨平台。AI 分析服务不解析 DEM，其运行时与部署平台另行验证。

## 3. 两条独立链路

### 3.1 知识积累链路

开始候选归纳前，P8.1 必须先完成来源去重、数据分组、保留集隔离及首轮评测协议冻结。归纳链路只能访问知识开发集；开发评测反馈可用于修订，但独立保留集不得用于生成或修订规则。

1. 授权维护者通过内部知识管线主动导入有来源记录的职业 DEM；后端复用解析与领域包，记录文件摘要、地图版本、解析器版本及覆盖情况。Desktop 不提供职业数据训练或知识管理入口。
2. 使用领域状态与确定性证据提取决策片段；有歧义或缺证据时不制造完整局面。
3. 代码统计与 AI 辅助归纳形成候选规律，关联支持案例、反例、条件和未知项。
4. 由具备游戏判断能力的人工审核，检查结果偏差、信息泄漏、替代解释和适用边界；AI 自评仅作辅助。
5. 在开发评测集上检验与修订，通过独立保留集发布门槛后形成正式知识版本。
6. 经内部发布渠道提供不可变知识快照，AI 分析服务验证版本/摘要后加载；记录发布与撤销历史，允许回滚。新增 DEM 不直接改写系统 Prompt 或正式规则。

候选规律、已审核规则、已发布知识版本和已废弃内容必须区分。比赛获胜、职业身份、案例数量或模型自信都不能单独证明规律正确。规则版本要能追溯原始证据和反例；地图或规则版本变化时重新检查适用性。

### 3.2 个人复盘链路

1. Desktop 本地 DEM → 现有 Match、Analytics、Deep Review、Findings，以及经过独立验证的新空间证据；个人 DEM 不上传服务端。
2. Desktop 构建决策时刻的最小证据请求，隔离未知敌情和未来结果，区分事实/推断/假设，并提供版本、覆盖与自身证据引用。用户发起 AI 分析时才提交必要结构化片段，不发送整场轨迹。
3. AI 分析服务验证访问权限、请求版本、大小、引用及信息边界，根据匹配的地图能力和知识适用条件加载只读已发布知识；不接受客户端指定任意系统 Prompt 或知识版本文件地址。
4. 后端按固定预算组装 Prompt、当前证据、相关规则与必要案例，并经模型适配层调用模型；不把整个数据库或整场 tick 数据送入模型。
5. 模型提出处理方案、依据、成立条件、风险和待确认因素；允许给出多个合理分支或说明无法判断。
6. 服务端校验结构、引用、数值、信息边界及已支持的空间约束，仅返回经筛选的教练结果 DTO。Desktop 再校验响应版本、结构和本地证据映射；失败或服务不可用时保留本地确定性报告。
7. 后端记录知识/Prompt/模型版本和校验摘要，按实现前确定的最小化及保留策略支持复现；不默认长期保存个人比赛证据或建立比赛历史。客户端仅接收必要版本标识，不接收原始 Prompt 或内部调用日志。

输出结构、引用格式和解析由后端保证；供应商支持的结构化输出或工具调用属于可选增强。无原生工具调用的模型可接收后端预先查询的相同证据。模型能力不足或输出校验失败时不承诺可用分析结果。请求的结构一致性不证明客户端提供的证据与原 DEM 真实、完整一致；建议须保持“基于所提交证据”的边界。

## 4. Prompt、知识与事实的职责

| 资产 | 负责内容 | 不负责内容 |
| --- | --- | --- |
| 固定 Prompt | 分析顺序、证据引用、未知项处理、输出格式 | 无限累积职业案例或伪装长期记忆 |
| 规则库 | 带条件、例外、支持与反对证据的决策原则 | 把一次成功操作升级为普遍结论 |
| 案例库 | 实际局面、行为、后续结果、来源和审核意见 | 用最终胜负直接标注当时选择的正确性 |
| 地图与计算工具 | 经过验证的空间、时间和资源事实 | 推测选手意图、听到的信息或敌人必然行为 |
| AI 模型 | 结合事实与规则解释，提出条件性方案 | 重新计算核心统计或自行发布规则 |

检索是知识装载机制，不能证明模型理解了决策。通用原则需围绕掩体关系、暴露方向、资源和时间约束表达；地图身份与几何仍须准确，跨地点泛化必须经测试。

## 5. 空间与信息能力门槛

- 现有 `MatchSpatialEvidence` 是事件附近的稀疏采样，不能当作完整移动轨迹、连续暴露过程或完整热力图。P6/P7 需各自设计并验证采样；保留实际 tick、缺失段与覆盖信息。
- P6 的 2D 回放提供观察与证据定位基础；P7 提供经过验证的分布统计。热力图不是残局最优决策的依据，也不构成 P8 所有能力的硬性技术依赖。
- 理解掩体、暴露角度和可行路线还需要独立的地图几何/拓扑能力验证。地图资产来源、合法使用、版本对应、坐标转换、静态遮挡与动态烟雾/门等状态必须分别处理。
- 地图几何获取与转换工具尚未选定。在该验证通过前，不提供“这条路线安全”“此处不会被看见”之类的确定性结论；2D 图或模型视觉判断不能补成已验证事实。
- 全局敌人真实位置可供事后事实核验，不能直接进入当时决策输入。几何 LOS 也不等于选手实际感知；无法可靠恢复的报点、声音和已知位置保持未知。
- 没有可靠动作、速度与时序证据时，不评价停枪质量、反应时间、精准瞄准等机械操作；同 tick 与缺失状态继续保留歧义。

## 6. 模块与安全边界

### 6.1 应用划分

| 规划应用 | 职责 | 可见性与访问边界 |
| --- | --- | --- |
| 现有 `apps/desktop` | 个人 DEM 本地解析、确定性分析、P6/P7、提交最小证据、展示教练建议 | 不持有职业库、系统 Prompt、供应商密钥或知识管理接口 |
| `apps/knowledge-pipeline`（规划） | 职业 DEM 导入、归纳、标注审核、隔离评测、知识发布与撤销 | 内部维护者使用；作业、管理接口、数据库和评测集不向客户端开放 |
| `apps/coach-api`（规划） | 客户端分析入口、已发布知识检索、几何查询、模型编排、输出校验 | 只开放经鉴权的受限分析接口；内部发布接口与供应商凭据不向客户端开放 |

两项后端应用独立构建、部署、运行和管理凭据；通过带版本和摘要的内部知识发布契约协作，不互相导入应用入口。共享契约及可复用领域逻辑放入 `packages/`，不放在 Electron 内。具体共享包名、HTTP 框架、作业执行方式和 API schema 在实施设计时确定，本轮不创建目录或公共 API。

### 6.2 领域与依赖方向

- `dem-parser`：唯一 native DEM 查询适配入口，负责所需新采样及来源映射。
- `match-model`：共享领域事实与正式空间契约；新增领域契约仍按领域模型工作流处理。
- `analytics / deep-review / findings`：纯确定性计算与已验证诊断，不访问数据库、网络或模型。
- 内部知识管线：组合解析、领域分析、知识存储、审核与评测，不把存储/模型逻辑塞进核心包；知识发布不依赖 Desktop。
- AI 分析服务：消费客户端证据契约、已发布知识与地图查询结果，构建有信息边界的请求；不接收个人 DEM，不重新解析个人比赛或计算其核心指标。
- 模型适配：后端处理供应商协议、超时、取消、重试和能力检测；Desktop 不直连模型，不携带供应商 SDK 或密钥。
- Desktop presenter / report-contract：按需新增经校验的 JSON 展示 DTO；面向服务的共享请求/响应契约另行定义，不把内部知识发布契约或模型协议透传 Renderer。

如候选规律需要升级为可检测的新诊断，应先走“规则定义 → 证据契约 → 确定性实现 → 验证 → 解释”流程。自然语言原则本身不授权 AI 新增确定性 Findings、技能评分或因果归责。

### 6.3 数据与访问控制

个人 DEM 和完整轨迹留在 Desktop；职业 DEM、知识库、系统 Prompt 和模型凭据留在受控后端。AI 分析服务仅接收必要个人证据，供应商仅接收后端为当前请求组装的必要内容。应用需显示外发范围；证据、日志与供应商保留策略在服务接入前确定。后端可适配云端或自托管模型，本路线不提供客户端直连或离线知识库模式。当前仍无后端实现与模型网络调用。

客户端只接收允许展示的方案、风险、自己的证据引用、可公开的解释和必要版本标识；原始知识快照、完整职业案例、内部规则文本、系统 Prompt、评测答案、原始模型响应与内部错误日志不通过结果或调试接口下发。解释可表达决策原则，但不开放知识管理或完整知识导出。

内部知识入口与客户端分析入口必须在部署、路由与权限上隔离，不能只隐藏客户端按钮。AI 分析服务对外开放前必须验证身份/访问凭据、授权、请求限制、限流与成本配额；不得在安装包内嵌长期共享服务密钥。具体鉴权方案需在 P8.1 确定，不等同于启动未来账号/比赛历史产品。

输入的玩家昵称、导入备注、案例文本和模型回复均为数据，不能覆盖系统规则、触发任意 SQL/代码执行或发布知识。后端控制允许的工具和检索查询；客户端身份不得取得内部归纳、评测、发布或快照下载权限。

## 7. 验证路线

这里只定义验证机制，不在本轮确定样本字段和评分量表，也不启动采集或评测。

1. 按完整比赛及其来源分组划分知识开发集、开发评测集和独立保留集；同一 DEM、重复下载、同一残局邻近片段不得跨集合。
2. 决策输入截止于决策时刻；后续结果和全局隐藏信息放入隔离的评测材料，不让模型或检索链路读到。
3. 用相同模型对比无职业知识与有已发布知识的结果，再用固定知识版本、相同证据比较不同模型；记录输入预算与重复运行，避免把随机性当成改进。
4. 程序校验事实引用、数值、结构和已支持的几何约束；人工评审决策合理性、条件、风险与替代方案。裁判模型不得作为唯一通过依据。
5. 对未见地点组合及局势做泛化检查；增加信息缺失、规则冲突和适用条件不满足的样本，检查是否正确保留未知或拒绝结论。
6. 发布门槛、评审量表和样本数量在评测工作单元开始前固定。保留集失败后的定向修改只能在新保留集上重新证明泛化，原失败结果不得抹去。
7. 每次知识或 Prompt 变更运行固定回归；已发布版本保持不可变。若引用造假、泄漏隐藏信息或输出无法支持的确定性结论，则该输出不能发布。
8. 后端接入需验证内部入口隔离、客户端授权、配额、知识快照只读加载/回滚，以及结果、错误和日志的私有资产泄漏检查；安装包不得包含后端私有知识、系统 Prompt 或供应商密钥。客户端请求不能覆盖知识版本或系统指令。

没有可靠模拟环境或受控实验时，不给未发生的路线编造胜率，不声称建议因果上优于实际行动。文字建议的审核通过不等于实战胜率提升；后者需要独立验证。

| P8.4 教练复盘 | AI 分析服务接入只读已发布知识、约束查询、后端模型编排及输出校验；Desktop 经鉴权 API 提交最小证据并联动展示 | 未开始 |
| P8.5 持续积累 | 在相同治理与回归下导入新 DEM，评估后续知识和模型版本 | 未开始 |

P8.1 的几何能力若未通过，需缩小并标示教练输出能力；不能以完成回放或接通模型替代此项验证。上述子阶段为本路线的规划，不表示已授权开始实现。
