# P8 AI Coach 范围决策：仅 L1 服务器事实与 L2 空间行动条件

日期：2026-10-25  
状态：**产品范围决策已记录；P8.1 验收契约待据此修订，阶段不自动转为 PASS。**  
适用项目：CS2 Analyst，现有版本保持 v0.2.0。

## 1. 决策

产品范围明确限定为：

- **L1：服务器事实复盘。** 使用 DEM 可核验的服务器侧状态、事件、时序、回合变化和数据覆盖，生成有证据引用的描述与复盘定位。
- **L2：空间与行动条件分析。** 在地图资源与版本、坐标映射、拓扑/碰撞/动态道具等能力通过独立验证后，分析距离、可达性、视线/遮挡、行动时间窗口及空间条件。
- **不实现 POV 视觉分析。** 不要求采集或处理玩家 POV 视频。
- **不推断玩家心理与实际注意力。** 不判断玩家是否真正看见敌人、是否注意到目标、是否听到声音、是否有某种主观意图。此类结论不是 L1/L2 目标。

本决策是对 P8 AI Coach 产品范围的收敛，不是对现有实现能力的夸大，也不代表地图几何或战术判断已经通过验证。

## 2. 对旧契约的解释与优先级

本决策用于修订 P8.1A 契约草案与 P8 技术路线中的能力边界。历史审计、P8.1A/P8.1B 的原始测试结果和报告保持不变，不重写历史记录。

与本决策冲突的旧草案内容按以下方式处理：

1. availableTick 不再作为所有 L1/L2 服务器事实描述的普遍硬门槛。它仍是玩家可获知时间的证据字段；缺失时不得宣称玩家当时已知该事实。
2. L1 使用独立、明确命名的 **ServerStateAtTick**（建议名称，尚非现有生产类型），表示 DEM 可重建的服务器侧历史事实。必须记录实际 tick、来源、覆盖、缺失/歧义与解析版本。
3. L2 使用独立的 **SpatialActionContext**（建议名称，尚非现有生产类型），只承载经验证的空间计算、所需输入和适用能力版本。
4. 不得把 ServerStateAtTick 伪装成玩家视角/认知状态；不得将服务器全局敌方位置写成“玩家已知敌人位置”。
5. 不得使用未来结果、最终胜负、后续死亡或完整回合统计改变决策时刻的历史输入、采样选择、缺失标记或证据引用。
6. 不得把理论 LOS 等同于实际看见，不得把距离等同于可支援性，不得把结果相关性等同于因果收益。

在 P8.1A 契约正式修订并审阅前，这是一项范围决策记录，不是对现有草案 API 的静默修改。

## 3. L1 验收边界

L1 可以陈述：

- 某玩家在特定 DEM tick 的服务器记录位置、朝向、血量、存活状态和阵营（字段存在且通过校验时）。
- 某个伤害、开火、击杀、道具或炸弹事件在何 tick 被记录。
- 同 tick 事件组、回合边界、人数变化及其不确定性。
- 事件之前/之后的服务器事实对比，但必须明确截断语义，不得制造同 tick 内无法证明的先后顺序。
- 解析器无法恢复、字段缺失或状态冲突的情况。

L1 不得自动推断：

- 玩家实际看到了什么或知道什么。
- 玩家注意力、反应意图、战术意图或心理状态。
- 未经验证的连续移动、瞄准/急停质量或精确反应时间。
- 某个动作导致胜负，或替代动作将提高多少胜率。

## 4. L2 验收边界

L2 的每一类几何结论都必须受能力门控。地图版本/坐标系/资源不匹配或未确认时，不能输出确定性战术结论。

- **位置/距离：** 可以在坐标和地图转换经过校验后计算；必须报告缺失和精度边界。
- **可达性/路线：** 需要经过验证的导航拓扑或可通行几何，不能由雷达图片或直线距离推断。
- **静态视线/遮挡：** 需要匹配版本的碰撞/遮挡数据；只表示理论几何关系，不表示玩家实际看见。
- **烟雾、火焰、门等动态条件：** 需要经过验证的时间与空间模型；静态射线不能替代动态效果。
- **支援/交叉火力：** 必须给出支撑结论的空间、时间和状态证据；单一距离阈值不足。
- **行动风险：** 只能表述条件性风险或历史关联，除非有独立有效的因果识别/受控实验，否则不得声称反事实胜率增益。

不支持的能力必须返回明确的 unknown/abstain 原因。语言模型不得填补缺失的几何事实。

## 5. P8.1B 的重新判定方式

P8.1B 原报告的历史结论 **BLOCKED / NOT PASS** 保持不变；它准确记录了当时按严格玩家可获知信息门槛执行的结果。范围决策不追认其为 PASS。

根据本决策，P8.1B 应另行进行一次**范围调整后的复核**，至少满足：

1. 真实白名单 Dust2 DEM 解析与字段覆盖证据可追溯。
2. 服务器事实与玩家感知字段分离；不存在把全局事实标记为玩家已知的错误。
3. 历史前缀输入、采样选择、缺失标记、证据引用和模型可见 metadata 不受未来事件影响。
4. L1 可描述事实的字段和覆盖门槛清晰，缺失/冲突时拒绝判断。
5. L2 能力按几何证据门槛分别验收；地图版本仍 unconfirmed 时，不宣称路线、LOS 或动态遮挡能力已通过。
6. 生产代码与既有产品行为未被未经授权地修改；所有命令与测试结果如实记录。

availableTick 的缺失不再单独阻断纯服务器事实描述，但仍阻断任何“玩家当时知道/看见/听见”的表述。现有 P8.1B 的未来事件预算竞争见证仍是有效问题；独立前缀查询/固定计划可以作为隔离方案，但必须重新验证范围调整后的完整输入。

## 6. P8.1C/D 与 P8.2 的状态

- **P8.1C：不自动放行。** 服务部署、native/SQLite 后端兼容、鉴权、配额、数据保留、模型适配与失败降级仍需验证。L2 的几何验证应只覆盖本阶段声明支持的能力，不能因范围调整而跳过。
- **P8.1D：不自动放行。** 来源与允许用途、去重、比赛/系列分组、训练/开发评测/独立保留集隔离、专家盲评与发布门槛仍需冻结。
- **P8.2：仍禁止进入。** 必须先完成重新定义后的 P8.1 门禁并获得明确签收。

## 7. 实施纪律

本次仅新增范围决策文档，不修改生产代码、版本号、模型、地图资产或现有验收证据。后续如需更新 P8 技术路线或 P8.1A 契约，应在单独聚焦变更中同步引用本决策并保留历史报告原文。

**核心原则：只实现 DEM 能证明的服务器事实，以及由经过验证的地图数据支持的空间/行动条件分析；不依赖 POV，不推断注意力，也不把服务器事实冒充玩家认知。**
