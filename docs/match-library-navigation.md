# CS2 Analyst · 比赛库与导航交互设计（规划）

> 状态：**设计已确认／尚未实施**。适用于未来 Windows x64 本地比赛历史功能；不进入 P8，不修改 P7 功能和版本号。
>
> **2026-10-18 导航方案修订：明确采用「全局侧栏 → 比赛详情上下文侧栏」的两种互斥模式。** 一级目录有「个人数据」「比赛数据」等入口；在比赛数据列表打开具体比赛后，侧栏**整体切换**为当前版本已有的六项比赛功能；单击标题栏返回即可退出该比赛、回到原列表。不是在侧栏把两级目录同时展开成树，也不新建一套比赛功能目录。
>
> 标题栏左侧有后退/前进，已有 App mark +「CS2 Analyst」组成的品牌整体**相对整个窗口绝对居中**。
>
> 对应：[比赛库实施规划](./match-library-plan.md) · [本地归档与容量设计](./match-library-storage.md)

## 1. 导航信息架构：两套互斥侧栏模式

```text
                  CS2 Analyst 标题栏
              [←] [→]       [mark + CS2 Analyst (整窗正中)]           [─][□][×]
                                 │
                 ┌───────────────┴───────────────┐
             全局导航模式                    比赛详情模式
     ┌──────────────────────┐         ┌─────────────────────────┐
     │ 个人数据             │         │ 比赛报告                │
     │ 比赛数据  ← 选中     │ ──打开→ │ 深度复盘                │
     │ 其他一级入口（待定） │         │ 回合时间线              │
     └──────────────────────┘         │ 分析                    │
     主内容：比赛数据列表             │ 比赛回放                │
                                     │ 热力图                  │
          ↑ 单击标题栏「后退」─────────└─────────────────────────┘
```

### 1.1 全局导航模式

- **全局侧栏第一层**包含「个人数据」「比赛数据」等顶层入口；这不是把「比赛报告/热力图」插入全局菜单。未来还可以增加其他同级功能，但现阶段只冻结两个已明确名称，**不替「个人数据」臆造统计功能或实施范围**。
- 「比赛数据」被选中时，主内容区展示**历史比赛列表/比赛库视图**；有记录时显示卡片/列表，初次使用或无记录时显示「选择 DEM / 拖放」空状态。应用默认进入「比赛数据」可作为首版默认入口；全局其他页面通过一级菜单进入。
- 比赛库负责本机历史的排序、筛选、打开、删除、导出/导入、容量与状态。摘要包括地图、可用比分、回合数、basename、导入时间、目标玩家（如有）、完整性/迁移状态。比赛实际时间只有真实证据时才展示，默认按导入时间倒序。
- 导入动作继续是用户主动选择/拖入，**不自动扫描本地 DEM**；不要求账号、网络服务，也不把数百场记录逐条变成侧栏子节点。
- 全局侧栏与比赛详情侧栏**绝不同时渲染为层级树**；处于「个人数据」「比赛数据」等全局一级页面时显示全局菜单，只有进入具体比赛工作区才显示比赛专属六项。

### 1.2 比赛详情模式（最小迁移原则）

- 点击「比赛数据」列表里某一场比赛，进入该比赛的工作区；**整个侧栏目录内容直接替换**为当前已实现的六项：比赛报告、深度复盘、回合时间线、分析、比赛回放、热力图。
- 六项的原有组件、顺序、名称、选中样式、折叠/底部动作和对应页面逻辑尽量原样复用；用**外层 shell 负责侧栏模式切换**，而非把每个分析页面重新搬到新嵌套路由里。
- 当前比赛由稳定的 `matchId` 确定，六个 Tab 仅作用于该场，不混合不同历史比赛数据；保留当前玩家选择和 Replay/Heatmap 的现有语义。
- **退出比赛的主路径是标题栏左上角「后退」**，单击回到进入该场之前的「比赛数据」列表位置/筛选状态，不额外要求比赛详情页添加顶部「返回比赛库」按钮或面包屑，以免形成重复操作。
- 标题栏「前进」可重新进入刚退出的那场比赛，恢复上次所选的比赛功能 Tab（能从本地 UI 状态安全恢复时）。不保证播放 tick、临时 IPC sessionId、Canvas 逐帧状态持久化。
- 在「个人数据」等其他一级功能中，沿用全局侧栏；只有进入**具体比赛**才切换为比赛详情侧栏。

### 1.3 路由及交互边界

建议两个层级的页面身份：`global/<section>` 与 `match/<matchId>`，当前比赛内部选中的六视图为 `matchView` 本地状态。实现可使用轻量 typed navigator，不强制引入 React Router 或重写全部 Tab。

**最重要的用户体验约束**：用户从比赛列表进入比赛以后，不论在该场切换了多少次「报告 / 热力图 / 回放」选项卡，标题栏**一次后退必须退出该场**，而不是先逐项回退 Tab 历史。这与旧文档原先把每次 Tab 切换都压入历史栈的设计不同；**旧规则作废**。

## 2. 标题栏设计（冻结约束）

当前代码：`apps/desktop/renderer/src/app-titlebar.tsx`，40px 无边框 Chromium/Electron 自绘标题栏，右侧 46px×3 窗口控制按钮，支持拖动及双击最大化。

```text
┌────────────────────────────────── 整个 BrowserWindow 宽度 W ─────────────────────────────────┐
│  [←] [→]       可拖动的空白区域       [mark] CS2 Analyst       空白       [─] [□] [×]          │
│  ↑左侧导航组                         ↑ LOGO+文字中心 x = W/2       ↑右侧系统控制组             │
└──────────────────────────────────────────────────────────────────────────────────────────────────┘
```

**严格居中不可退让：**
1. mark + 文本形成一个整体品牌组，其**中心坐标必须是 BrowserWindow 客户区完整宽度的 50%**，并非去除左侧按钮、右侧窗口控制按钮后的剩余区域中心。
2. 禁止只使用 `display:flex; justify-content:space-between`、不对称的左右 Flex 或把页面工作区中心当作标题中心来制造“伪居中”。优先标题栏 `position:relative` + 品牌组 `position:absolute; left:50%; transform:translateX(-50%)`；等价方案需通过精确几何验收。
3. 标题栏左侧放**后退**和**前进**两个图标按钮，参考用户提供的 Codex 桌面端截图。未有历史时 disabled；hover/focus 有 Tooltip 和 aria-label，焦点环可见。图标与 Windows 标题栏保持低噪、克制，不把页面标题、回合控件挤进标题栏。
4. 右侧继续使用现有最小化/最大化/还原/关闭逻辑及大小，保留关闭 hover 红色、Windows 最大化状态订阅。品牌组仍使用**已有** `cs2-analyst-mark.png` 和正式名称，不换视觉资产。
5. 布局冲突时先缩短非必要文字或收敛辅助按钮间距、合理限制品牌组最大宽度/ellipsis；**不得通过偏移品牌组中心解决碰撞**。最低支持窗口宽度、缩放/DPI 及未来新增按钮必须纳入几何验收；极端窄窗口有明确降级策略。
6. 标题栏拖拽区域与可点击区域分清：所有交互按钮是 `-webkit-app-region: no-drag`，空白与非交互品牌区可拖动；双击最大化/还原仍正常；不要让全屏透明元素遮挡控制、拖拽或 Tooltip。
7. 保持键盘操作、Windows 高对比度/forced-colors、屏幕阅读器标签和禁用态可辨识性，复用 Fluent UI v9。

**几何验收公式**：`abs(brandRect.left + brandRect.width / 2 - titlebarRect.left - titlebarRect.width / 2) <= 1 CSS px`。分别在 1024×640、1920×1032、恢复/最大化、左侧侧栏收起/展开条件下验证；DPI 125%/150% 如环境允许实测，否则明确标记人工待验，不能虚报。后退/前进按钮不应改变中心测量。

## 3. 后退／前进语义

标题栏按钮导航的是**全局页面及比赛工作区进出历史**，不是 CS2 Replay 进度条：

- 历史节点记录 `global(section)` 或 `match(matchId)` 两种页面身份；**比赛详情六个 Tab 切换不入浏览历史栈**。它们属于当前比赛工作区内部状态。
- 典型场景：全局「比赛数据」列表 → 打开 A → 切换 A 的热力图/回放 → 单击「后退」**直接返回比赛数据列表**；再按「前进」重新打开 A，侧栏切回比赛详情六项。
- 从「个人数据」跳到「比赛数据」属于正常全局导航，前进/后退按真实页面栈变化；进入 A 前所在的全局页面是返回目的地，通常是比赛数据列表。
- 在历史中途打开新页面或另一个比赛，清空前进分支；同一页面重复触发不重复压栈；按钮禁用准确反映 `canBack/canForward`。
- 不将播放器 tick/暂停/倍速、当前玩家、热力图筛选、弹窗开闭等状态压栈。每场当前选中的功能 Tab 可以作为小型可恢复状态记录，但不得使“退出比赛”需要按多次后退。
- 比赛详情退回全局导航时，释放不再使用的 Replay/Heatmap 临时会话，或按经验证的生命周期策略延迟释放；「前进」重新进入时创建可信新会话，不能复用过期 UUID。
- 导入成功后打开新比赛工作区；用户取消导入或解析失败时不污染导航栈，并保留原有页面/列表与数据。
- 后退/前进命中已删除、损坏、版本不兼容的比赛：安全降级到比赛数据列表并提示，不白屏、不误开另一场。
- 应用重启默认回到全局「比赛数据」页面；是否持久保存路由/比赛视图状态作为后续独立决策。

## 4. 当前代码的最小改造边界

现状为单份 `useReport` 和六项 `Sidebar` 导航，Utility Process 中的 ReplaySession / HeatmapSession 使用临时 sessionId。未来引入外层的 `AppShell` / 轻量导航状态（名称为建议，非要求创建新框架）：

1. **全局模式**：Sidebar 渲染「个人数据、比赛数据」等一级项目；主内容加载轻量比赛库索引（不解析全库 Replay）。
2. **比赛模式**：Sidebar 复用现有的**六项菜单定义与选项卡组件**；主内容加载当前比赛报告，Replay / Heatmap 仍按已有方式使用分块 IPC。
3. **模式切换发生在 Shell 层**：以 `currentMatchId !== null` 等明确导航状态控制侧栏菜单集，不让六个功能页面都自己处理导航返回；不需要重复编写六个页面或大规模迁移现有布局。
4. **标题栏独立于两种模式**：整窗几何居中的品牌和左侧前进/后退按钮始终存在，右侧窗口控制始终有效。
5. **持久化职责不落 Renderer**：Main/Utility 管 SQLite 与压缩档案，Renderer 只通过可信 IPC 取当前比赛数据；跨比赛切换防竞态、旧回包、失效会话污染。
6. **侧栏展开/收起**及详情模式原有「重新选择 DEM」等操作保留，具体是否在全局模式另提供导入按钮由 L4 UI 阶段依据现有体验确定；不要为了菜单切换推翻单场已有功能。

## 5. 可用性验收清单

1. 全局导航显示「个人数据」「比赛数据」等一级目录；进入「比赛数据」展示可操作的比赛列表或正确空状态。尚未实施的「个人数据」不得伪装为可用业务页。
2. 从比赛列表进入 A 后，左侧目录**整体切换为现有六项**，没有残留全局导航，也没有出现“全局 → 六项”的二级树。
3. 在 A 内反复切换多次报告/热力图/回放等 Tab，单击标题栏「后退」**直接返回比赛数据列表**，且列表滚动、筛选条件尽量保持；按「前进」重新进入 A，恢复该场上次所选视图。
4. 测试「个人数据（若已实现）→ 比赛数据 → A → 后退 → 前进」以及 A/B 两场切换、删除比赛后历史失效降级、导入取消/失败和前进分支清除。
5. 品牌组严格按**整个窗口**几何中心计量，左后退/前进和右窗口按钮都不影响中心；保留拖拽/双击最大化/窗口控制。
6. 已保存比赛在原 DEM 不存在时六个功能仍可用；跨场请求/Replay/Heatmap 会话不泄漏或错绑；大小库初屏不加载全部 Chunk。
7. 真实 Electron 分别检查 1024×640、1920×1032、侧栏展开/折叠、窗口恢复/最大化、Tooltip/键盘/高对比度；未验证的 DPI 不声称 PASS。
8. **最小迁移回归**：现有六个比赛视图、菜单样式、切换玩家、原报告/Deep Review、回放和热力图功能保持不变。

当前仅确定设计，不代表 UI、比赛库或数据功能已经交付。
