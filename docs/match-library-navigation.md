# CS2 Analyst · 比赛库与导航交互设计（规划）

> 状态：**设计已确认／尚未实施**。适用于未来的 Windows x64 本地比赛历史功能；不进入 P8，不修改 P7 功能和版本号。
>
> 决策来源：用户明确否决“全局导航 + 当前比赛二级导航”的旧建议，指定参考 Codex 桌面端的**标题栏后退／前进**，并把现有 App mark + “CS2 Analyst”放到**整个窗口正中央**。下文不把被否决的左侧两级导航方案当成最终设计。
>
> 对应：[比赛库实施规划](./match-library-plan.md) · [本地归档与容量设计](./match-library-storage.md)

## 1. 信息架构

- **比赛库（Library）**成为应用正常启动后的主页：已有历史时显示比赛列表；首次使用或库空时显示现有“选择 DEM / 拖放”的友好空状态。
- 打开一场比赛后进入该场的工作区。**保留现有侧栏六项**：比赛报告、深度复盘、回合时间线、分析、比赛回放、热力图。它们始终针对当前打开的比赛；**不把所有比赛逐条塞入侧栏，也不改成此前被否决的全局/二级树结构**。
- 提供显式“返回比赛库”入口：在比赛详情的顶部内容区提供返回/面包屑动作，库页面可直接打开比赛；标题栏后退/前进也能完成页面历史导航。具体视觉细节在 UI 阶段打磨，不提前增加第二套复杂侧栏。
- 导入操作继续由用户主动触发；不自动扫描 CS2/Steam 文件夹、下载 DEM 或批量发现录像。
- 历史记录本机可用，不依赖登录/网络；当前比赛数据仅在对应比赛中展示，不跨比赛混合统计或复盘证据。
- “比赛库”负责：地图/时间/文件名/对局身份摘要、排序与筛选、容量显示、删除、导出、导入归档和打开。建议默认按**导入时间倒序**，比赛实际时间只有可信来源时才显示/排序。筛选与搜索按实测需求逐步增加。
- 比赛卡片最小元数据：地图、比分（可能未知）、回合数、原始 DEM 文件名（非路径）、导入时间、目标玩家昵称及数据状态（完整/局部不可用/需要迁移）；同名 DEM 不是唯一键，稳定主键采用归档 Match ID。

## 2. 标题栏设计（冻结约束）

当前代码：`apps/desktop/renderer/src/app-titlebar.tsx`，40px 无边框 Chromium/Electron 自绘标题栏，右侧 46px×3 窗口控制按钮，支持拖动及双击最大化。

```text
┌────────────────────────────────── 整个 BrowserWindow 宽度 W ─────────────────────────────────┐
│  [←] [→]       可拖动的空白区域       [mark] CS2 Analyst       空白       [─] [□] [×]          │
│  ↑左侧导航组                         ↑ LOGO+文字中心 x = W/2       ↑右侧系统控制组             │
└──────────────────────────────────────────────────────────────────────────────────────────────────┘
```

**严格居中不可退让：**
1. mark + 文本形成一个整体品牌组，其**中心坐标必须是 BrowserWindow 客户区完整宽度的 50%**，并非去除左侧按钮、右侧窗口控制按钮后的剩余区域中心。
2. 禁止只使用 `display:flex; justify-content:space-between`、不对称的左右 Flex 或把页面工作区中心当作标题中心来制造“伪居中”。优先标题栏 `position:relative` + 品牌组 `position:absolute; left:50%; transform:translateX(-50%)`；等价方案需通过精确几何验收。
3. 标题栏左侧放**后退**和**前进**两个图标按钮，参考用户提供的 Codex 桌面端截图。未有历史时 disabled；hover/focus 有 Tooltip 和 aria-label，焦点环可见。图标与 Windows 标题栏保持低噪、克制，不把页面标题、回合控件挤进标题栏。
4. 右侧继续使用现有最小化/最大化/还原/关闭逻辑及大小，保留关闭 hover 红色、Windows 最大化状态订阅。品牌组仍使用**已有** `cs2-analyst-mark.png` 和正式名称，不换视觉资产。
5. 布局冲突时先缩短非必要文字或收敛辅助按钮间距、合理限制品牌组最大宽度/ellipsis；**不得通过偏移品牌组中心解决碰撞**。最低支持窗口宽度、缩放/DPI 及未来新增按钮必须纳入几何验收；极端窄窗口有明确降级策略。
6. 标题栏拖拽区域与可点击区域分清：所有交互按钮是 `-webkit-app-region: no-drag`，空白与非交互品牌区可拖动；双击最大化/还原仍正常；不要让全屏透明元素遮挡控制、拖拽或 Tooltip。
7. 保持键盘操作、Windows 高对比度/forced-colors、屏幕阅读器标签和禁用态可辨识性，复用 Fluent UI v9。

**几何验收公式**：`abs(brandRect.left + brandRect.width / 2 - titlebarRect.left - titlebarRect.width / 2) <= 1 CSS px`。分别在 1024×640、1920×1032、恢复/最大化、左侧侧栏收起/展开条件下验证；DPI 125%/150% 如环境允许实测，否则明确标记人工待验，不能虚报。后退/前进按钮不应改变中心测量。

## 3. 后退／前进语义

标题栏按钮导航的是**应用页面历史**，不是 CS2 Replay 进度条：
- 可入栈的目标：`library`、`match/:matchId/report`、`match/:matchId/deep-review`、`timeline`、`analysis`、`replay`、`heatmap`（实际用 typed route + view 枚举）；从某场跳转到另一场也是一次导航。
- 用户打开比赛库中一场记录 → 历史入栈；切换该比赛六个分析视图 → 新视图入栈；后退再前进按实际访问次序恢复。
- 在历史中间执行新的显式导航时，清空前进分支；同一路由重复点击不重复压栈；禁用按钮准确反映 `canBack/canForward`。
- **不**将播放器播放/暂停、tick seek、倍速、热力图筛选、选中玩家变化、弹窗开闭逐项压栈；否则按几次回退就要跨过数千个播放动作。
- 最小恢复内容：`matchId + view`；建议按每场缓存目标玩家/最后使用视图作为 UI 偏好，但不混入历史路径身份。不保证离开再返回后 Replay 仍处于原 tick，除非后续单独定义“保存播放位置”。
- 导入完成导航到新比赛的报告；取消导入、解析失败不污染历史栈，原比赛/比赛库仍可用。
- 后退/前进命中**已删除、损坏或不兼容**的比赛：不要白屏或打开其他比赛；跳过失效历史条目并提示返回比赛库。
- 应用重启：默认进入比赛库；是否记忆最后打开比赛属于后续可选设置，不作为首版前提。

## 4. 当前会话与页面行为

现状单比赛：`useReport` 仅一份 report，`Sidebar` 六项 Tab；Utility Process 的 ReplaySession / HeatmapSession 依赖临时 UUID。未来增加 `MatchLibrary` 和 `CurrentMatch` 两层职责，不能把数据库塞进 Renderer 状态 Store。

- 库主页只请求轻量索引和摘要；点击某场才加载该场报告。
- 已保存比赛无需 DEM，即可进入六个视图。打开时由 Main/Utility **新建临时会话 ID** 并从已验证的本地档案按需读取 Replay Chunk、热力图证据。
- 切换历史比赛须明确 release 前一场活动 Replay/Heatmap 会话，重建新会话；确保异步旧请求不会污染新比赛。
- 比赛列表大时虚拟化/分页，而不是全量把所有报告导入 React；列表检索不反序列化 Replay。
- 当前手动导入、拖放、错误降级、侧栏折叠及六视图内部行为继续保留。无需新增账号菜单或服务状态入口。

## 5. 可用性验收清单

1. 窗口标题居中严格按整个窗口计量，左后退/前进和右窗口按钮不影响中心。
2. 历史返回/前进穿越“比赛库 → A 的报告 → A 的回放 → B 的热力图”等路径正确，禁用态正确。
3. 退回比赛库不丢失已保存的比赛；重新打开历史比赛在**原 DEM 不存在**时仍可查看全部已存功能。
4. 切比赛/反复开关标签后没有旧会话泄漏、跨场错绑、失效的热力图/Replay IPC。
5. 六个现有比赛视图不改导航名称/业务口径；不采用旧提案中全局导航树结构。
6. 1024×640、1920×1032、侧栏展开收起、窗口拖动/双击/恢复/最大化，以及 Tooltip/键盘/高对比度状态均有真实 Electron 证据。

当前仅确定设计，不代表 UI 或数据功能已交付。
