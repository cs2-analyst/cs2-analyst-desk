## 2. 当前可复用事实与禁止捷径

| 已有资产 | 复用方式 | 不得直接推出的结论 |

## 3. 首个决策问题与切片

首个问题限定为：**Dust2 1v1 刚形成后，哪些信息足以描述局面，哪些选择仍无资格评价？** 本轮不评价完整回合，不要求输出唯一最优策略。

候选发现与决策输入是两条链。离线完整证据可以用于发现候选、质量检查和标签，但由此得出的最后死亡时刻、最终片段长度、全局覆盖率及筛选理由不进入模型。筛选引入的选择偏差必须在数据集记录中保留。

建议初始锚点：同 tick 原子死亡组 g 完成后，使用 `cutTick = g + 1`、`phase = before-tick`。需检查安全整数、正式回合及边界可信度；不能排序同 tick 事件制造 g 内的先后，也不在回合结束后创建虚假决策。

“候选 1v1”还需独立核验：截止锚点可确认双方各有一名存活玩家，目标玩家在其中，未发现截至该时刻的生命周期歧义。完整回合 resolver 可以辅助离线核验，不能代替前缀 resolver。端点发现与实际玩家下一次动作不等价。

**本轮实验未实现候选发现、前缀存活 resolver 或 DEM 提取。** 示例中的双方人数由合成的可信公开观察提供。是否能由现有数据可靠构造这些观察，是 P8.1B 的实证任务。

## 4. 时间与知识边界

采用保守的 `before-tick` 截断：仅接纳 `observedTick < cutTick` 且 `availableTick < cutTick` 的事实。`observedTick` 是事实发生/被采样的时间，`availableTick` 是证据渠道使观察者可获得它的时间，且后者不得早于前者。

原生 final-tick 状态不能成为同 tick 动作前输入。此策略会损失部分信息，不能冒称恢复了 subtick 精度。将来采用更细粒度时间，必须新增证据并另行版本化。

| 信息 | 首批策略 |
| --- | --- |
| 自身位置、血量、阵营 | 仅由已验证的 self-state 映射产生；保留实际采样时刻及来源 |
| 双方存活人数等公开信息 | 需要独立验证公开语义和前缀恢复；不能仅因 DEM 有字段就当作公开 |
| 敌人真实位置、视角、装备 | 默认不可输入；全局实体记录只能作离线事实/标签 |
| 最后已知敌人位置 | 当前没有经过验证的观察适配器，保持 unknown；不能直接使用 relevant 样本 |
| 语音、报点、声音、注意力 | 不可恢复部分为 unknown，不默认听到或注意到 |
| 静态 LOS、烟火显示效果 | 不等于实际看见，也不自动证明动态遮挡 |
| 未来结果、完整 Engagement、全回合 coverage | 放入离线材料，禁止进入输入、检索条件和模型可见诊断 |

`unknown` 必须显式编码，不能填 0、空坐标或“没有敌人”。缺帧、无效字段与互相冲突的观察不得伪造为完整状态。新观察标记 unavailable 时，不得回退旧值并称其为当前真值。

旧观察可作为“在 t 时已知”的历史事实，但不得无条件前向填充为当前事实。正式实现需为每类字段确定失效条件与 fresh/stale 规则；实验中的 `maxAgeTicks=20` **只是合成测试参数，不是游戏标准或推荐阈值**。尚无可靠时钟时，不将 tick 换算成秒。

## 5. 契约分层草案

以下是职责与最小字段草案，不是现有 public API。正式共享类型和运行时校验应进入 `packages/`；本轮实验留在 `docs/experiments/`，不得被应用导入。

| 对象 | 最小内容 | 访问边界 |
| --- | --- | --- |
| CorpusManifest | 原 DEM 摘要、来源/允许用途、比赛分组、真实比赛日期、游戏/地图/解析器版本、split、标注协议 | 内部研究管线；不发送给模型 |
| DecisionEpisodeIndex | 锚点、地图、回合、目标玩家本地标识、任务/提取器版本、候选/离线质检来源 | 内部索引；不是模型输入 |
| InformationState | observer、cut、历史窗口、已知/未知事实、采样时刻、信息来源与不确定性 | 仅由受验证的规范化器产生 |
| ChosenAction / Outcome | 行为证据和结果分别存储；无法恢复意图则未知 | 标注/评测隔离，不传入决策模型或检索过滤 |
| CoachEvidenceBundle | 已允许的事实、局部引用别名、任务、允许能力、未知项 | 服务/模型白名单投影，不能展开完整 Episode |
| CoachAssessment | 事实解释、条件性建议、依据、缺失条件、拒绝原因、知识/模型/校验版本 | 经程序和语义门控后展示；本轮未实现生成 |

建议事实变体：

```text
KnownFact = {
  status: known,
  value,
  observedTick,
  availableTick,
  sourceChannel,
  localEvidenceRef
}
UnknownFact = {
  status: unknown,
  reason: not-observed | unavailable | stale | conflicting | unsupported
}
```

字段名、unknown 原因枚举及 JSON schema 在正式契约冻结时统一；上述示意不表示现有类型已经变更。`sourceChannel` 是证据分类，不是自证可信的字符串或签名。

**两个信任边界不能混淆：**

1. 规范化器要验证原始记录和来源，才能断言某观察属于自身或公开渠道。
2. 投影器仅将已规范化信息筛入允许输入。它不能通过检查 `audience: self` 字符串证明该记录真实。

客户端证据的格式一致性也不证明与原 DEM 完全一致。未来服务只可承诺“基于提交并通过能力检查的证据”，不能伪装为服务端重读个人 DEM。

## 6. 引用与隐私

本地完整引用仍可关联 DEM 哈希、sourceRevision、解析/采样版本、回合、actualTick、eventIndex 或特定行键；eventIndex 不证明 subtick 先后。这些原始引用由本地/受控后端保管。

给模型的引用必须是当前请求内的局部别名，映射到已允许的事实。别名生成不得依赖被过滤的全局/未来行数量。不要把 DEM 内容哈希、原始 SteamID、昵称、文件路径、未来结果或全回合诊断偷偷带进模型的 metadata。

服务 envelope 与模型 body 分离。最小请求的字段、字节预算、授权、伪名化、日志/供应商保留策略仍需在服务实现前冻结；本轮没有网络请求，也没有声称隐私边界已完成产品验收。未知自由文本和昵称均按数据处理，不得变成指令。

## 7. 任务证据门槛

`eligible-for-description` 仅表示可以准确陈述相关已知事实，不表示“决策正确”，也不表示可以生成任意语言结论。

| 任务 | 必需证据 | 当前结果 |
| --- | --- | --- |
| 描述已知自身/公开事实 | 可信来源、合法时间、有效数值、可回溯引用 | 实验可描述合成已知事实；真实适配未验证 |
| 评价路线安全、暴露、选位 | 匹配的地图版本、通路/遮挡、敌情不确定性、可执行状态 | abstain；禁止补造安全结论 |
| 建议具体道具选择 | 持有量、动作可行性、时间和经过验证的效果空间 | abstain；有投掷事件不等于当前仍有道具 |
| 评价急停/瞄准/反应 | 可靠动作、速度、准星与精细时间语义 | abstain；事件间隔不是反应时间 |
| 给替代行动的精确胜率增益 | 已验证反事实方法、适用假设与校准 | abstain；不得由历史相关性伪装因果提升 |

几何版本仍 unconfirmed 时，可保留示意图回放和不依赖几何的事实描述，但不能允许对应的战术判断。future AI 回复即使 JSON 合法、引用存在，也要核对数值和结论是否被证据支持。

## 8. 因果稳定性要求

令 `I(o, t, D)` 为观察者 o、截断时刻 t 下的模型可见输入。当 D 与 D' 的合法观察前缀相同，仅隐藏全局状态或未来变化时，应满足 `I(o,t,D) = I(o,t,D')`。比较包括值、缺失标记、引用别名与模型可见 metadata，不只是主数值。

必须区分：**投影稳定不代表采样稳定。** 现有空间采样器用全场 core tick 数量分配 optional 预算，可能因未来事件变化而删除早期采样。不能先使用这种输入，再靠删除 future 字段宣称端到端无泄漏。

后续策略要求固定且版本化的前缀采样计划，或独立于未来数量的局部有界查询。不可用显示插值替代真实观测；不能为了模型任务修改原来的离线复盘语义。离线质量筛选可依赖完整数据，但相应选择偏差须报告，不把未来决定的筛选标记给模型。

## 12. 范围决策修订（2026-10-25，当前解释）

依据 [P8 L1/L2 范围决策](./p8-scope-decision-l1-l2-2026-10-25.md)，本节修订前文草案的适用范围。前文保留为 P8.1A 原始设计记录；不再将玩家认知模型理解为 L1/L2 全部能力的普遍硬门槛。

### 12.1 当前目标

- L1 服务器事实复盘：以 DEM 能核验的服务器侧事实、事件、tick、回合状态、覆盖与证据引用为依据。
- L2 空间/行动条件分析：仅在地图版本、坐标、拓扑/碰撞、静态/动态遮挡等对应能力经独立验证后，分析空间关系与行动条件。
- 不实现 POV 画面分析，不推断玩家实际看见、注意、听见或心理/主观意图。

### 12.2 时间与信息边界

`observedTick`、真实采样 tick、来源、解析版本、覆盖与歧义仍必须保留。`availableTick` 不再作为纯服务器事实描述的普遍硬门槛，但缺失时不能声称玩家在该时刻已知事实。服务器全局状态必须标注为服务器事实，不得伪装成玩家视角。

未来事件不得改变截断时刻的历史输入、采样选择、缺失/覆盖标记、证据引用或模型可见 metadata。既有离线全局预算采样器的前缀不稳定见证仍有效；须用独立前缀查询或固定计划隔离，不修改既有离线复盘语义来掩盖问题。

### 12.3 规划中的职责名（不是生产 API）

- `ServerStateAtTick`：服务器侧历史事实、实际 tick、来源、解析/地图版本、覆盖和未知项。
- `SpatialActionContext`：经验证的地图空间查询、输入引用、能力版本、适用条件和失败/拒绝原因。

两者不得合并成玩家认知状态。L2 的理论 LOS 不表示玩家实际看见；距离不自动表示可支援；相关性不自动证明因果收益。地图版本未确认时，不得输出确定性路线安全、LOS 或动态遮挡结论。

### 12.4 阶段门禁

P8.1B 原始报告的 `BLOCKED / NOT PASS` 是历史事实，保留不变。必须按 L1/L2 重新评估前缀稳定性、服务器事实字段与几何能力边界；不能仅因 `availableTick` 不再阻断 L1，就将整个 B 阶段追认为 PASS。P8.1C/D 不自动放行，P8.2 仍禁止进入，直至按新范围完成 P8.1 验收并获得明确签收。
